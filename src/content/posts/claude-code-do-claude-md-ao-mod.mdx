Em 01/10/2026, o Claude Code ganhou os **mods**: plugins com código que roda dentro do programa, reage ao que acontece na sessão, guarda estado e desenha na interface. [O anúncio](https://claude.com/blog/claude-code-mods) veio com a versão 2.1.287. Até ali, tudo o que se instalava no Claude Code entregava texto ou ferramentas ao modelo, ou rodava um script por fora.

Este post explica o que é um mod e como o Claude Code chegou até ele: as peças de extensão que vieram antes, com a data de cada uma, o que cada uma faz e o que só o mod faz. O texto parte do zero. Não pressupõe conhecer skill, agente, hook, plugin nem marketplace, e aponta a documentação oficial para quem quiser se aprofundar. Não é um tutorial de código.

> [!NOTA] Parte 1 de 2
> Esta parte explica as peças e o mod. A [parte 2](/posts/claude-code-csr-cockpit/) parte de um mod pronto, o csr-cockpit, e mostra o painel, a instalação, os testes e os limites.

## A linha do tempo

O Claude Code foi lançado em 24/02/2025, como [prévia de pesquisa](https://www.anthropic.com/news/claude-3-7-sonnet), e os mods chegaram em 01/10/2026. São pouco mais de :circulo[19 meses], e nesse intervalo o Claude Code ganhou, uma depois da outra, as peças desta tabela:

| Quando | Peça |
|---|---|
| 24/02/2025 (lançamento) | **`CLAUDE.md` e MCP**: um texto que o modelo lê em toda sessão, e ferramentas trazidas de fora |
| 05/03/2025 (0.2.31) | **Comandos próprios**: um prompt salvo, chamado por `/nome` |
| 30/06/2025 (1.0.38) | **Hooks**: um comando do sistema que roda sozinho num evento da sessão |
| 24/07/2025 (1.0.60) | **Subagentes**: um ajudante com papel e contexto próprios |
| 07/08/2025 (1.0.71) | **Linha de status**: uma linha no rodapé, escrita por um script seu |
| 14/08/2025 (1.0.81) | **Estilos de saída**: um jeito de responder |
| [09/10/2025](https://claude.com/blog/claude-code-plugins) (2.0.12) | **Plugins e marketplaces**: a embalagem que junta as peças, e o catálogo de onde ela se instala |
| [16/10/2025](https://claude.com/blog/skills) (2.0.20) | **Skills**: instruções que o modelo carrega quando o pedido combina com a descrição delas |
| 22/04/2026 (2.1.118) | **Temas próprios**: as cores da interface |
| 01/10/2026 (2.1.287) | **Mods**: código que roda dentro do Claude Code e desenha na tela |

Entre parênteses está a versão em que a peça entrou. Cada data é a da publicação dessa versão no [npm](https://www.npmjs.com/package/@anthropic-ai/claude-code?activeTab=versions), e a linha de cada peça está no [changelog do repositório](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md).

O `CLAUDE.md` e o MCP são a exceção: não têm linha no changelog, porque já estavam na [documentação do dia do lançamento](https://web.archive.org/web/20250224200833/https://docs.anthropic.com/en/docs/agents-and-tools/claude-code/tutorials).

A tabela pode ser lida como uma escada, com a mesma pergunta em cada degrau: essa peça consegue pôr algo novo na interface? O exemplo mais claro é um painel ao lado da conversa, que mostre o que a sessão está fazendo. Para responder, uma distinção ajuda. O **modelo** é a IA, o Claude: lê texto e responde. O **Claude Code** é o programa que você abre no terminal: manda o texto ao modelo, executa as ferramentas que ele pede (ler um arquivo, rodar um comando) e desenha a tela. :grifo[Um painel só pode vir do programa.]

Mais um termo, que volta nas duas partes. Tudo o que o modelo tem na frente para responder (as instruções, a conversa, os arquivos lidos) é o [contexto](https://code.claude.com/docs/en/context-window). Ele tem tamanho máximo e é medido em tokens, os pedaços de palavra em que o modelo conta o texto e pelos quais se cobra.

## Cada peça e o que ela não alcança

A ordem aqui é a de quem aprende, não a das datas: a skill vem antes do plugin, que é a embalagem das outras. Os exemplos vêm do [claude-code-kit](https://github.com/cesarschutz/claude-code-kit), o repositório público que acompanha as duas partes, com exemplos pequenos de seis delas (hook, subagente, estilo de saída, skill, plugin e tema) e um mod.

**`CLAUDE.md`.** Um arquivo de texto, em geral na raiz do projeto, que o Claude Code entrega ao modelo no começo de toda sessão. É onde ficam as [instruções permanentes](https://code.claude.com/docs/en/memory#claude-md-files): como rodar os testes, as convenções do time, o que nunca fazer. Use para o que :ondulado[vale sempre]. Na interface ele não mexe: é texto para o modelo ler.

**MCP.** O [Model Context Protocol](https://code.claude.com/docs/en/mcp) liga o modelo a sistemas de fora: um servidor MCP entrega ferramentas novas, como consultar um banco de dados ou controlar um navegador. Use quando o modelo precisa alcançar algo que ele não enxerga. A interface continua a mesma: o MCP dá ferramentas ao modelo.

**Comando.** Um prompt salvo num arquivo Markdown, que você chama digitando `/nome`. Serve para o pedido que se repete toda semana. Poupa a digitação, e só: :grifo[o que chega ao modelo é o mesmo texto].

**Hook.** Na forma mais comum, um comando do sistema que o Claude Code roda sozinho num evento: no início da sessão, antes de uma ferramenta, depois de uma edição. É a peça para o que [tem de acontecer sempre](https://code.claude.com/docs/en/hooks-guide), sem depender de o modelo lembrar. O exemplo do kit é o [`responder-em-portugues`](https://github.com/cesarschutz/claude-code-kit/tree/main/hooks/responder-em-portugues), um `echo` no início da sessão. Das peças antigas, é a que vê os eventos passarem. Só que roda :nota[fora do Claude Code]{texto="o mod vai rodar dentro"}, como um processo à parte, e não desenha nada.

**Subagente.** Um ajudante com papel próprio, ferramentas limitadas e :explica[um contexto só dele]{nota="não ocupa o da conversa"}, que faz a tarefa e devolve um resumo. É o que a documentação chama de agente. Use para [isolar o trabalho](https://code.claude.com/docs/en/sub-agents) que encheria a conversa principal, como uma busca em dezenas de arquivos. No kit há dois, o [`pesquisador`](https://github.com/cesarschutz/claude-code-kit/blob/main/agents/pesquisador.md) e o `critico`, cada um definido por um arquivo de instruções. Na tela nada muda: o que volta é texto.

**Linha de status.** Uma linha no rodapé, impressa por um script seu, que recebe do Claude Code os [dados da sessão](https://code.claude.com/docs/en/statusline#available-data), como o modelo em uso e o custo. É a peça que mais se parece com um painel. Mas é :ondulado[uma linha só], sem clique.

**Estilo de saída.** Um [jeito de responder](https://code.claude.com/docs/en/output-styles): o papel, o tom e o formato das respostas de uma sessão. O [`professor`](https://github.com/cesarschutz/claude-code-kit/blob/main/output-styles/professor.md) do kit explica o porquê de cada passo, e o estilo se escolhe com `/output-style`. Muda o texto da resposta, não a tela.

**Skill.** Uma pasta com um arquivo `SKILL.md`: [instruções](https://code.claude.com/docs/en/skills) que o modelo carrega quando o pedido combina com a descrição, ou quando você chama pelo nome. É a peça para o procedimento que você vive colando na conversa. :aparte[Os comandos próprios, lá de cima, foram incorporados às skills, e os arquivos antigos continuam funcionando.] No kit, a [`mensagem-de-commit`](https://github.com/cesarschutz/claude-code-kit/blob/main/skills/mensagem-de-commit/SKILL.md) escreve a mensagem de commit das mudanças já preparadas com `git add`. Como o `CLAUDE.md`, a skill é texto para o modelo: a tela fica igual.

**Plugin.** É a embalagem: uma [pasta](https://code.claude.com/docs/en/plugins/overview#understand-what-a-plugin-is) com skills, agentes, hooks, estilos e servidores MCP, que se instala de uma vez. Dentro dela, o arquivo `.claude-plugin/plugin.json` é o manifesto, que descreve o plugin. Use quando um segundo projeto, ou uma segunda pessoa, precisa da mesma configuração. O [`exemplos`](https://github.com/cesarschutz/claude-code-kit/tree/main/plugins/exemplos) do kit leva uma skill, um agente, um hook e um estilo de saída. Sozinho, o plugin não acrescenta poder nenhum: :duplo[empacota o que já existia].

**Tema.** As [cores da interface](https://code.claude.com/docs/en/terminal-config#create-a-custom-theme), num arquivo JSON que parte de um tema pronto e troca algumas cores. O [`tinta-azul`](https://github.com/cesarschutz/claude-code-kit/blob/main/themes/tinta-azul/themes/tinta-azul.json) troca três, e o tema se escolhe com `/theme`. Muda a cor do que já está na tela.

:::colchete
Nenhuma dessas peças põe um painel na interface. O `CLAUDE.md`, o comando, o subagente, o estilo e a skill são texto para o modelo. O MCP dá ferramentas a ele. O hook e a linha de status rodam um script do lado de fora. O plugin embala, e o tema troca cores. Faltava a peça que roda por dentro.
:::

## O que é um mod

O mod é um plugin com uma diferença. Num plugin comum, o arquivo `hooks/hooks.json` lista os hooks: que comando do sistema rodar em cada evento. No mod, o mesmo arquivo :duplo[aponta um módulo], que é um arquivo de código.

```json title="plugins/csr-cockpit/hooks/hooks.json" anotar="./register.tsx|o código do mod"
{ "modules": ["./register.tsx"] }
```

Esse módulo exporta uma função `register(on)`. Dentro dela, cada `on(...)` liga uma função a um evento do Claude Code: uma chamada de ferramenta, o início de um turno (cada pedido feito na sessão), um pedaço da interface sendo desenhado. A função recebe três coisas: `$`, a API dos mods; `e`, o evento; e `next`, que passa o evento adiante, como num :nota[middleware]{texto="quem não chama next responde no lugar"}. A documentação também chama de hook cada função dessas.

Este é um hook do csr-cockpit, o mod da parte 2: quando o Claude Code cria um subagente (o evento `agent.spawn`), o hook deixa o evento seguir e anota o agente e o pedido dele. O miolo está resumido num comentário:

```tsx title="plugins/csr-cockpit/hooks/register.tsx" linhas="3|o evento segue adiante como chegou"
export const register: Register = on => {
  on('agent.spawn', async ($, e, next) => {
    const iniciado = await next(e)
    // guarda o agente e o pedido dele no estado da sessão
    return iniciado
  })
}
```

A ideia é a do hook de antes, reagir a um evento, só que agora é código rodando dentro do Claude Code, que pode [observar o evento, reescrevê-lo ou responder no lugar](https://code.claude.com/docs/en/plugins/mods/overview#what-a-hook-can-do-with-an-event) do programa. Com isso, um mod:

- roda dentro do Claude Code, no processo dele, e não como um script à parte;
- guarda estado (lembra o que viu) entre um evento e outro, pelo tempo da sessão;
- registra um comando `/nome` que executa código na hora, sem passar pelo modelo;
- desenha: um painel ao lado da conversa e uma faixa acima do prompt, a caixa onde se digita o pedido.

Das peças da tabela, é :marca[a primeira que roda ali dentro e a primeira que desenha um painel].

A figura junta as peças no lugar em que cada uma age. Do lado de fora ficam o texto que vai para o contexto do modelo (azul), as ferramentas do MCP (âmbar) e o script do hook (verde), quase tudo dentro da pasta do plugin (roxo). Do lado de dentro, só o mod (petróleo): o código dele vem na mesma pasta, recebe os eventos, guarda estado e desenha o painel e a faixa. Com o mouse numa cor da legenda, só aquele papel fica aceso.

:::validade{data="out/2026"}
Os mods passaram por um [período de acesso antecipado](https://github.com/anthropics/claude-code/commit/d9c456d7dba722727cc06146ca45580eaa18b914) em setembro de 2026, só para quem ligava uma variável de ambiente, e são [oficiais a partir da 2.1.287](https://code.claude.com/docs/en/plugins/mods/overview#turn-mods-on-or-off), ligados por padrão.
:::

Eles [funcionam no terminal e na aba Code do aplicativo de desktop](https://code.claude.com/docs/en/plugins/mods/overview#where-mods-run). O aplicativo traz a própria cópia do Claude Code, que pode estar numa versão anterior à do terminal: `claude --version` mostra a versão do terminal, não a do aplicativo.

> [!ATENCAO]
> Um mod é código que roda com as suas permissões, sem isolamento: pode ler e gravar arquivos, iniciar processos e usar a rede. A documentação tem uma seção sobre [como decidir se confia num mod](https://code.claude.com/docs/en/plugins/mods/overview#decide-whether-to-trust-a-mod). Instale só mods de autores em quem você confia e, antes de instalar, leia o código ou rode `claude plugin validate <pasta>`, que lista os eventos que o mod escuta e as chamadas que ele faz, sem executar nada.

## Skill, agente ou plugin: as confusões mais comuns

Os nomes se parecem, e é fácil tomar uma peça pela outra. Estas são as confusões que mais aparecem para quem está começando:

- **Skill, agente e plugin não são alternativas.** A skill é uma instrução. O agente é quem executa uma tarefa numa conversa à parte. O plugin é a pasta que entrega os dois.
- **Mod é plugin, não skill.** A skill é um texto que o modelo lê. O mod é código que :ondulado[o Claude Code executa]. Os dois chegam dentro de um plugin, instalado do mesmo jeito.
- **O mod não tem build.** Nada de `npm install` nem de empacotador: o Claude Code [lê o código direto](https://code.claude.com/docs/en/plugins/mods/create#write-a-mod-yourself) da pasta.
- **Não se instala uma skill solta de dentro de um plugin.** A unidade de instalação é o plugin, e tudo o que está na pasta dele vem junto.
- **Marketplace não é uma loja.** É o catálogo de onde os plugins se instalam: um repositório git com um arquivo que lista os itens. :grifo[Um repositório público no GitHub basta], sem conta empresarial. A parte 2 mostra um por dentro.
